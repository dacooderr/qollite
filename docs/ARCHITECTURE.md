# Architecture

How QOL Lite is put together: what the repository actually contains, how the game loads it, and the
Panorama facts that shape every design decision here.

---

## 1. Provenance — what this repository is

**Read this before editing anything.** The repository is not a conventional source tree.

Until 2026-08-04 the repo stored release `.vpk` files. Commit `959f80e` ("reformatting for Easy
version control") replaced the packed VPK with its **extracted and decompiled contents**, so that
changes between versions become reviewable diffs instead of a binary blob.

That leaves three different kinds of file, and they are not equally editable:

| Kind | Files | What it is | Editable? |
|---|---|---|---|
| **Decompiled** | `panorama/**/*.xml`, `panorama/**/*.css`, `materials/**/*.vmat`, `models/**/*.vmdl` | Reconstructed by Source 2 Viewer from the compiled `_c` artifacts. Every one carries a `<!-- ... reconstructed by Source 2 Viewer -->` or `/* Prettified by Source 2 Viewer */` header. | Readable and diffable. Recompiling them is possible but the output is not guaranteed byte-identical to what the original author compiled — see [`FIELD_NOTES.md`](FIELD_NOTES.md) §1 for what that has already cost. |
| **Script source** | `panorama/scripts/*.js` | The VPK holds each script compiled as `.vjs_c`, a resource wrapping the JS text unchanged, so the source here is the exact code the game runs. They carry no decompiler header. **A new `.js` file ships only if the build compiles it** — nothing in the game falls back to the raw file. | Depends on the script — see below. |
| **Extracted binary** | `*.png`, `*.dmx`, `*.vtex`, `*.vpcf` | Textures, meshes and particle definitions pulled out of the pack. | Only by replacing them. |

### Scripts: which ones are source and which are build output

The scripts fall into these groups (measured 2026-09-30 in the working tree):

| Scripts | Form | Where the source lives |
|---|---|---|
| `qollite_map_*.js` (15) | **Readable** upstream source, each file opening with a provenance header (upstream repo, commit, original file name, rename rule) | The BetterMap repository. Regenerated by `scripts/bundle_bettermap.py` — see §8 and [`BUNDLE.md`](BUNDLE.md) §3 |
| `qollite_notifications_*.js` (11) | **Readable** upstream source with a provenance header | The Map Event Reminders repository. Regenerated by `scripts/bundle_mer.py` |
| `friends_rank.js`, `friends_rank_config.js`, `friends_rank_scoreboard.js` | Readable (indented, commented), no provenance header | Unknown — not recorded anywhere in the repo |
| everything else — `qollite_topbar`, `qollite_quickbuy`, `qollite_recent_purchases`, `qollite_recent_purchase_icons`, `qollite_hero_testing`, `qollite_leaderboard`, `qollite_passive`, `qollite_profile`, `mercurial_magnum_notifier` | **Minified Closure Compiler output** — single-letter identifiers, flattened structure, no comments | Not in this repository, and for most of them unknown ([`TECH_DEBT.md`](TECH_DEBT.md) §5). Five of them are included by no layout (§3) |

Until 2026-09-30 the map and notification scripts were minified too; they were re-bundled from their
upstream commits as readable source on that date. The remaining minified files look like this
(`qollite_passive.js`):

```js
(function(){function f(b,a){b==="enabled"&&c.SetHasClass("ASAPOn",a);b==="compact"&&c.SetHasClass("ASAPCompact",a)} ...
```

Consequences:

- **First-party bundles are regenerated, not edited.** A hand-edit to `qollite_map_*.js` or
  `qollite_notifications_*.js` is overwritten by the next bundle run. Change upstream, then
  re-bundle; a change that must exist only in QOL Lite becomes a recorded delta in the bundler and in
  [`BUNDLE.md`](BUNDLE.md).
- **Minified scripts have no reviewable source here.** Editing them by hand is possible but produces
  code nobody can review, and the next regeneration from real source silently discards it. Before
  changing their behaviour, find the upstream. If it cannot be found, say so explicitly rather than
  patching the minified output as if it were source.

A separate consequence: `[BetterMap]` still appears in log prefixes inside `qollite_map_*.js`, and
markers still use `bm_`/`Bm` prefixes; the notification scripts keep `[NOTIF]` prefixes and the UMM
id `eventnotifier`. Those are upstream names the bundlers keep on purpose — CSS, saved UMM values and
log filters match them — not dead code.

├── images/        11 mod-authored textures (21 files: .png sources + .vtex)

materials/         material overrides + 1×1 stub textures
models/            replacement meshes (McGinnis wall) and material overrides
particles/         replacement particle systems (McGinnis wall)

231 files in total (measured 2026-09-30 on branch `fix/remerge-6722`, uncommitted — the same file set

`base/` and `topbar_rank_base/` directories, and the stylesheets and images a mod added under its
own name (`friends_rank*`, `mercurial_magnum_notifier`, `notif`, `topbar_rank_topbar`, …). Shipping

there is no patch or hook system. `scripts/rebase_overrides.py` enumerates them: at the 6722 rebase
it checked 80 files — the Valve-path overrides, the `base/` copies, and one mod-named fork (§9).

## 3. Load model

Panorama has no module system and no bundler. A layout `.xml` declares, in order:

1. `<styles>` — stylesheets to load
2. `<scripts>` — scripts to load, executed top to bottom in that layout's context
3. the panel tree

Scripts loaded by a layout run **in that layout's JavaScript context**. Two layouts do not share a
global scope, do not see each other's variables, and cannot call each other's functions. This is the
single most important structural constraint in the mod; §6 covers how features work around it.

### The `.js` vs `.vjs_c` split in `<include>`

Some includes name `.js`, others `.vjs_c`:

```xml
<include src="s2r://panorama/scripts/qollite_map_log.js" />       <!-- raw -->
<include src="s2r://panorama/scripts/qollite_passive.vjs_c" />    <!-- compiled -->
```

Both resolve to the same script. The extension records how the file was referenced when the layout
was compiled. Keep whichever form a layout already uses; changing it without reason risks a
resolution failure that Panorama reports only as "the feature silently did nothing".

## 4. The `base/` pattern

`panorama/styles/base/` and `panorama/styles/topbar_rank_base/` hold **pristine copies of Valve
stylesheets under mod-invented paths**. Nothing in the game loads them directly; they exist so an
override can `@import` the original and then append to it:

```css
/* panorama/styles/citadel_ui_ability_order.css */
@import url("s2r://panorama/styles/base/citadel_ui_ability_order.vcss_c");
.AspectRatio4x3 .gEditingBuilds #AbilityBuildContainer { ui-scale: 88%; }
```

This is how several merged mods can extend the same Valve stylesheet without each shipping a full
divergent fork of it.

**Some of these files are confusing to read, and the reason is decompilation.** Panorama's compiler
flattens `@import` into the compiled `.vcss_c`, so the decompiler can emit *both* the original
`@import` line *and* the inlined result — an overlay that appears to contain its own base twice. That
is a decompiler artifact, **not** duplicated content in the shipped file. Since `4bb5c0e` only two
overlays still show it, `hud.css` and `hud_ability_icon.css`; the rest are `@import`-only (see below).

Rules that follow:

- `base/**` is **read-only reference**. Never edit it to change behaviour — edit the override. After
  a game patch it is refreshed to the new Valve file (§9), which is the whole point of keeping it
  pristine.
- Do not judge a file's real size or content from the decompiled text.
- **Not every copy is pristine.** All 16 copies were diffed against Valve 6722 on 2026-09-30
  (header line and `.vcss`/`.vcss_c` form ignored). Twelve are exact. Four carry mod values:
  `base/citadel_hud_top_bar_chat.css` (two `margin-top: 75px`),
  `topbar_rank_base/citadel_hud_top_bar.css` (one `visibility: visible`), `topbar_rank_base/objectives_map.css`
  (`.IconCtn` 110 % instead of 100 %) and
  `base/hud_ability_icon_passive.css` (four values around its lines 1023–1059, unchanged since before
  the 6722 update). `base/hud.css` used to carry `#objectives_health_friendly` `margin-top: 100px`; it
  is exact Valve 6722 since `4bb5c0e`, and the override `hud.css` still sets that rule (`110px`), so
  the behaviour did not change.
- Three of these copies are loaded by nothing at all — `base/citadel_hud_top_bar.css`,
  `base/citadel_hud_top_bar_chat.css`, `topbar_rank_base/citadel_hud_top_bar.css`; see
  [`TECH_DEBT.md`](TECH_DEBT.md) § Dead files.

## 5. Panorama notes

The engine facts that constrain what can be built here have their own page:
**[`PANORAMA.md`](PANORAMA.md)** — read it before touching any layout, style, or script.

The five that shape the most decisions:

- **No storage, file, or convar API.** Nothing a script writes survives a restart on its own;
  persistence is delegated to Universal Mod Manager (see [`UMM.md`](UMM.md)).
- **No timers other than `$.Schedule`.** Every recurring behaviour in this mod is a self-re-arming
  schedule — and therefore a standing frame cost. See [`TECH_DEBT.md`](TECH_DEBT.md) § Polling budget.
- **Contexts are isolated** (§3). The only bridge is the event bus in §6.
- **Panel operations cannot report failure.** Judge success by reading observable state back.
- **Load order is undefined.** Poll for dependencies; never assume another script's global exists.

## 6. Cross-context communication

`$.DispatchEvent("ClientUI_FireOutput", <string>)` is broadcast to **every** Panorama context, and
`$.RegisterForUnhandledEvent("ClientUI_FireOutput", fn)` receives it. It is the only bridge between
layouts, and this mod uses it as a shared message bus with JSON payloads.

Three protocols currently share the bus. Receivers must tolerate messages that are not theirs — the
established idiom is a cheap substring test before parsing:

```js
if (typeof s === "string" && s.indexOf('"umm"') !== -1) { /* try JSON.parse */ }
```

| Discriminator | Protocol | Documented in |
|---|---|---|
| `{"umm":1, ...}` | Universal Mod Manager settings | [`UMM.md`](UMM.md) |
| `{"notif":1,"type":"clock","t":<seconds>}` | match clock, top bar → notification overlay | [event reminders](systems/event-reminders.md) |
| `{"notif":1,"type":"lang","lang":"<id>"}` | detected UI language, top bar → notification overlay | [event reminders](systems/event-reminders.md) |
| `{"notif":1,"type":"urn"}` | urn-spawn edge, top bar → notification overlay | [event reminders](systems/event-reminders.md) |

**Adding a protocol:** pick a new top-level discriminator key, keep the substring guard, and add a
row here.

One receiver skips the guard: `qollite_notifications_clock.js` → `onMessage` `JSON.parse`s every bus
message before checking `notif`/`type` (upstream code, bundled unchanged; proposed upstream in
[`TECH_DEBT.md`](TECH_DEBT.md) D2).

## 8. Build and release

Compilation and packing are **manual and performed outside this repository**. The workflow implied
by the git history is: edit the tree → compile Panorama and asset sources → pack into
`pak01_dir.vpk` → publish the VPK as the release artifact. The repo tracks the reviewable tree;
release VPKs are not committed.

What the repo *does* regenerate, with tools under `scripts/`:

| Tool | Regenerates | Usage |
|---|---|---|
| `scripts/bundle_bettermap.py` | `panorama/scripts/qollite_map_*.js` from a BetterMap commit | `--upstream <BetterMap checkout> --rev <commit> [--check]` |
| `scripts/bundle_mer.py` | `panorama/scripts/qollite_notifications_*.js` from a Map Event Reminders commit | `--upstream <MapEventReminders checkout> --rev <commit> [--check]` |
| `scripts/rebase_overrides.py` | every Valve-path override, carried onto a new game build (§9) | `--tracker <clone> --old <rev> --new <rev> [--apply] [--out <dir>]` |

Both bundlers read upstream through `git show` at the given commit — never the upstream working
tree — apply the rename table and the recorded QOL Lite deltas, and fail rather than write if a delta
anchor no longer matches exactly once. `--check` compares without writing (exit 1 on a difference).
Offline tests: `python scripts/test_bundle.py`, `python scripts/test_rebase_overrides.py`.

**What the bundlers do not touch:** the layouts and stylesheets a first-party mod also needs —
`hud.xml`'s script list and settings window, `hud_minimap.css`, the BetterMap rules in `hud.css`,
`base_hud_and_db_overlay.xml`, `notif.css`. Those live in the merge layer and are updated by hand
against upstream's own copies; [`BUNDLE.md`](BUNDLE.md) §3 records what was compared.

This answers, for the two first-party mods, the question this section used to leave open (what
regenerates `panorama/scripts/*.js`). For the minified vendored scripts it is still open — see §1.

## 9. After a game patch

A Deadlock patch changes Valve's layouts and stylesheets under our overrides without telling anyone.
Nothing fails loudly: a full-copy override keeps shipping the old Valve file, new Valve panels go
unstyled or missing, and a script looking for a removed panel just stops finding it
([`FIELD_NOTES.md`](FIELD_NOTES.md) §6). This is the procedure used for the 6722 update
(2026-09-30). Every step's output is **unverified until checked in game**.

### 1. Get Valve's history

Clone SteamDatabase's GameTracking-Deadlock tracker; a blobless clone is enough
(`git clone --filter=blob:none --no-checkout …`). Identify two tracker revisions: the last build the
overrides were made against, and the target build. For this update: `33e0801209` (6701) →
`245f2952f9` (6722). The large patch was 6711 (`58b3529`); 6722 is a same-day follow-up and is the
build targeted here.

### 2. Run the rebase

```
python scripts/rebase_overrides.py --tracker <clone> --old 33e0801209 --new 245f2952f9 --out <dir outside the repo>
python scripts/rebase_overrides.py ... --apply      # write results into the working tree
```

For each file it picks a base (the tracker revision with the smallest diff against ours), merges
`ours + (theirs − base)` with `git merge-file --diff3`, and writes `report.json`. Statuses:
`valve-unchanged` (nothing to do), `valve-copy` (no mod delta — the result is simply the new Valve
file), `modded`, `review-base`. `--apply` writes every result except `review-base`, **including
conflicted ones**, which keep their diff3 markers. The default `--out` is `qollite_rebase_out` in
the system temp directory, so nothing the tool writes lands in the repo.

At 6722: 80 files checked, 22 needed a human (conflicts or `review-base`).

### 3. Resolve conflicts, then check every result

Resolve markers by hand, then for each file: no markers left; CSS braces balance; XML parses; the
decompiler header line is kept; and `diff <new Valve file> <result>` shows **only the mod's own
lines** — every Valve line present, every removal one the mod made on purpose.

### 4. Review the base picks — the heuristic is wrong in known shapes

- **`@import`-only overlays** (eleven since `4bb5c0e`, listed in §4; at 6722 only `hud_abilities.css`
  and `citadel_db_page_profile.css`). They hold no Valve copy, so the smallest-diff "base" is an
  unrelated old Valve file and the merge grafts a whole Valve sheet into the overlay. Correct
  handling: **keep the override unchanged** — its Valve content arrives through the refreshed `base/`
  copy.
- **Full replacements** (`hud_hero_testing.xml`, `hero_testing_menu.css`). The mod replaces Valve's
  panel wholesale, so every candidate differs by ~1,400 lines and the merge replays Valve's entire
  history into the mod. Correct handling: discard the merge and port only the build-to-build changes
  the mod's own markup depends on (for 6722: removed panel events rebound to convars — see
  [`BUNDLE.md`](BUNDLE.md) §4).
- **A subtly wrong base the tool cannot flag.** `hud_escape_menu.xml` was auto-based on `d8d5f3e`,
  older than its real fork point `5372faa`, because a mod wrapper happened to cancel part of a later
  Valve move and so shrank the diff. The evidence for the real base was line provenance: the mod
  carried markup Valve introduced in `5372faa`. Re-merged against `5372faa`: zero conflicts. The ratio
  check in the tool (`REVIEW_DELTA_RATIO`) cannot catch this shape; only reading the diff does.

### 5. Mod-named forks of Valve files

A fork stored under a mod path is invisible to a tool that walks Valve paths.
`topbar_rank_topbar.css` is a full fork of Valve's `citadel_hud_top_bar.css` and is **the only
top-bar stylesheet the per-player rows load** ([`FIELD_NOTES.md`](FIELD_NOTES.md) §7). Skipped by the
first rebase run, it kept pre-patch values for 18 of the 60 selectors Valve changed in 6711 and lacked the new
`PlayerHeroReleaseVote` rules, so the rows' "Voted!" label would have had no rule hiding it
(inferred from the cascade, not seen in game). Such files are listed in `ALIASES` in
`scripts/rebase_overrides.py`; add any new one there.

### 6. Know Valve's reference forms

Since 6711 Valve's compiled files reference stylesheets as `.vcss`; this repo uses `.vcss_c`. Both
resolve, per the rebase tool's notes (§3 describes the same split for scripts). The rebase tool normalises Valve's form to ours so the churn stays out of the merge —
do not "fix" existing references by hand.

### 7. Check the scripts' panel lookups against the new layouts

The rebase covers layouts and styles only. Every id and class a script looks up has to be re-checked
against the new Valve layouts, because a missing panel costs more than a missing feature: a polling
`FindChildTraverse` for a panel that no longer exists **walks the whole tree on every tick**
([`FIELD_NOTES.md`](FIELD_NOTES.md) §8). 6711 deleted `#map_render`, which four scripts anchored on;
two of them polled for it at ~17 Hz and 4 Hz. Fixed upstream in BetterMap, then re-bundled.

### 8. Re-bundle the first-party mods

Pull the upstream commits that target the new build and run `bundle_bettermap.py` /

### 9. Trap: a local tree pasted over a merged one reverts it silently

`4bb5c0e` committed a local tree, fixed independently from the pre-patch `5adefb4`, on top of the
merged rebase `1f0fe0f`. Git saw ordinary edits, so about 20 rebased files silently went back to
pre-patch content. Symptoms: BetterMap vanished from UMM (`hud.xml` had the old 12-script list, so
its bootstrap gave up waiting for Minimap / Player / Preview), and "Voted!" stayed on the player
rows (the pasted `topbar_rank_topbar.css` was the pre-patch fork, with no vote rules).

The pasted tree also held Valve 6722 copies of layouts and stylesheets the mod overrides, which
dropped features **unintentionally** — the maintainer confirmed he meant to remove none: recent
purchases (`citadel_hud_hero_shop.xml` and its rules in `citadel_hud_hero_shop.css`), the ammo-buff
notifier (`ability_hud_elements/element_gun.xml`), the mod's hero-testing panel (`hud_hero_testing.xml`,
`hero_testing_menu.css`), and Friends Rank's MVP-card markup (`post_game/citadel_db_post_game_team.xml`)
with the Statlocker rules of `citadel_db_page_profile.css`. All of them were restored from `1f0fe0f`.
One Valve copy was a fix: it stopped a crash on the post-game MVP screen, whose cause is unknown —
the restored MVP-card layout is an open risk ([`TECH_DEBT.md`](TECH_DEBT.md) D17).

A diff against the parent cannot tell a fix from a revert. **Detect it with a 3-way classification
against the common ancestor:** `git merge-file --diff3 <theirs> <ancestor> <ours>` per touched file.
A hunk where one side still equals the ancestor was changed by the other side only, so that change
wins (the parent diff showed it as a revert); a hunk changed on both sides is resolved against the
new Valve file. A removal that breaks a still-loaded script is restored. A feature whose markup and
script include vanished together is **not** evidence of a deliberate removal — a pasted Valve copy
does exactly that — so ask the maintainer before leaving it out. Branch `fix/remerge-6722` was built this way; it changed contents only,
so the file list the build must compile is the same as at `4bb5c0e`.
